# 量産フロー：どう回すか

「毎日つくる」を"毎日の作業"にしないのがコツです。**まとめて先に作り、投稿は予約 or 決まった時間に流すだけ**にします。

---

## 全体像

```
[1] 内容を事前チェック   scripts/export_schedule.py / make.py --no-video
        ↓
[2] 1ヶ月分を一括生成    scripts/make.py --date <月初> --days 30
        ↓  output/<日付>_<テーマ>/ に画像・動画・キャプションが揃う
[3] 音を付ける           TikTokアプリでトレンド音源/商用ライブラリを適用（推奨）
        ↓
[4] 投稿                 予約投稿 or 毎朝1本アップ
        ↓
[5] 数字を見て型を寄せる  伸びたテーマ/音/時間に集中（strategy.md 参照）
```

---

## ステップ詳細

### [1] まず内容を確認する（動画を作る前に）
半年分のスケジュールと"1位ハイライト"を一覧で確認できます。

```bash
python scripts/export_schedule.py --date 2026-08-01 --days 182
# -> docs/schedule.csv（全量）と docs/schedule_preview.md（先頭5週間の表）
```

内容の文言や配色を直したくなったら:
- メッセージ・ラッキー要素 … `fortune/data.py`
- 配色 … `fortune/data.py` の `PALETTES`
- レイアウト … `templates/ranking.html`

画像だけ先に量産して目視チェック（動画化は後回し・速い）:
```bash
python scripts/make.py --date 2026-08-01 --days 30 --no-video
```

### [2] 1ヶ月分を一括生成
```bash
# BGMを付けて動画まで作る場合（assets/bgm に音源を置いてから）
python scripts/make.py --date 2026-08-01 --days 30 --bgm assets/bgm/loop.mp3 --duration 12
```
- `--duration` で尺（秒）を調整。まずは 8〜15 秒でOK。1分版にするなら 60。
- 生成物は `output/2026-08-01_zodiac_overall/` のように**日付＋テーマのフォルダ**に整理されます。

### [3] 音を付ける（重要・ここでリーチが決まる）
BGMの選び方は2通り。**基本は後者（アプリ内）を推奨**します。

1. **手元のBGMを焼き込む**（`--bgm`）
   - メリット：完成ファイルがそのまま完結。YouTubeショート等へ流用しやすい。
   - 注意：**必ず商用利用OK・TikTok投稿OKの音源**を使うこと（フリーBGM配布サイトの規約を確認、クレジット表記が必要なものも）。著作権のある曲の焼き込みはNG。
2. **TikTokアプリ内でトレンド音源／商用楽曲ライブラリを当てる**（おすすめ）
   - メリット：**発見(おすすめ)に乗りやすい**＝再生が伸びる。著作権も安全。オリジナル性判定にもプラス。
   - やり方：本キットで作った**無音（or 仮BGM）動画**をアプリにアップ → 編集画面で「楽曲を追加」→ 急上昇/おすすめの音源を選ぶ。
   - この運用なら `make.py` は `--bgm` 無し（無音）で回してOK。音はアプリ側で毎回付ける。

> 迷ったら：**無音で量産 → アプリでトレンド音源を都度適用**。これが再生数・著作権・手間のバランスが最良です。

### [4] 投稿する
- **予約投稿**：TikTok（Webのアップロード画面 or アプリ）に予約投稿機能があります。1ヶ月分を数回に分けて予約しておけば"毎日の作業ゼロ"に近づきます。
- **手動**：占いは朝が強いので、毎朝7〜9時に1本。ルーティン化する。
- **キャプション**：各フォルダの `caption.txt` をコピペ。冒頭フック＋ハッシュタグが入っています。

### [5] 数字を見て寄せる
- TikTokアナリティクスで「平均視聴時間・視聴完了率・保存・コメント・シェア」を見る。
- 伸びたテーマ/音/投稿時間を特定 → `WEEKLY_ROTATION`（`fortune/schedule.py`）を編集して**当たり枠を増やす**。
- 詳しい判断基準は [strategy.md](strategy.md) の「4. 続けるかの判断」。

---

## 運用を軽くする小ワザ

- **月初にまとめ作業**：毎月1日に翌月分30日をバッチ生成 → 予約投稿。実作業は月1回。
- **テンプレ複製で新テーマ**：`templates/ranking.html` をコピーして別デザインを増やせば、飽き対策＆A/Bテストになる。
- **命名で管理**：`output/<日付>_<テーマ>/` 固定なので、投稿済みフォルダは別ディレクトリに移すだけで進捗管理できる。
- **内容の再現性**：生成は日付シードで決定論的。作り直しても同じ内容になるので「あの日のを再生成」も安全。

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| 文字が豆腐（□）になる | フォント未取得。`python scripts/fetch_fonts.py` を実行 |
| `node ... playwright` で失敗 | `npm root -g` に playwright があるか確認。無ければ `npm i -g playwright` |
| 動画が作れない（ffmpeg not found） | `ffmpeg` を導入（`apt-get install ffmpeg` 等） |
| BGMが途中で切れる/長すぎる | `--duration` を音源に合わせて調整（BGMは自動ループ＆終端フェード） |
| 画像は良いが動きが欲しい | strategy.md「1分以上・飽きさせない構成」を参照（12位→1位めくり等） |
